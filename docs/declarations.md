# tmux-workplace declaration layers

Structure, Access, Agents and Host are the shared base layers for a workplace. The optional Identity layer declares which seats hold keys. Optional Homes and Runtime layers declare a kind's private program home and required runtime environment names. Optional Comms and Logs layers record communication reach and pane-recording policy. The optional SSH layer names key files and records scoped grants. The Typify reader validates programs and prints their terms. The frame executes the primitives and applies the recorded policy. For a complete planning example with the released reader, start with the [five-seat W4 workplace](../tests/fixtures/ssh-workplace/README.md).

`LanguageDeclarations.typify` assembles the four current base bodies in that order with one header. A configuration's `workplace.json` selects relative layer paths, and the frame assembles their complete bodies without editing lines. The Identity fixture additionally selects Identity. Shared layers contain no workplace identity or chosen filesystem root. Source files contain no comments.

Resource paths use `workplace-path`, the ordinary union of canonical absolute paths, canonical relative paths and `.`. Both captures and receiving signatures preserve the authored string. The frame joins relative resource slots before folding and applying them. A directory's first authored value supplies Start's directory context; the reader no longer joins it. A command's program path inside JSON is checked and resolved by the frame, while subsequent words and environment values remain literal. [The path-slot inventory](path-slots.md) lists every position and the exact boundary.

In `programs/WORKPLACE.typify`, declare `clearance-scale : turned` when using clearances or labels. Zero is the highest clearance. A room takes its own clearance if declared, otherwise its office's. Its seats share that number. A numbered label clears a room whose number is at most the label's number. A `closed` label clears no room. A seat can still carry its own `view` statements. The frame resolves the effective view using those statements, ancestor paths and label rules. The [frame contract](../CONTRACT.md) specifies the fold.

A flat kinds registry declares each name once, and a seat selects a registered kind or none. Native ensures and counts reject unknown, absent, duplicate and mixed selections. Kind shared places use ordinary view statements. A private program home is a separate declaration of the optional Homes layer, never a shared writable kind directory. The interface remains the six executable names server, session, window, pane, arrange and start. Provenance paths remain relative source addresses; they are never resource slots. The Structure body checks display-name uniqueness but does not independently reject different display names sharing a seat key; the frame retains its structural checks.

For any integration use a fresh isolated root and a new configuration clone. Never replace an existing workplace. The frame generates exactly `workdir : ROOT` and `server : NAME : CONF`, each with a newline, where ROOT is the actual root, NAME follows the clone-path rule, and CONF is the raw configuration path. Program addresses and source line counts are preserved. No command here starts a server.
