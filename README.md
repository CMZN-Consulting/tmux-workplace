# tmux-workplace declaration layers

Structure, Access, Agents and Host are the shared base layers for a workplace. The optional Identity layer declares which seats hold keys. The accepted Typify reader at `4bb7584a88a4e59bd1295f56f771a3f434e5d7ea` validates the programs and prints their terms; the frame gives the executable primitives and recorded policy their meaning. This branch is an authoring fixture, not a deployed workplace.

`LanguageDeclarations.typify` assembles the four current base bodies in that order with one header. A configuration's `workplace.json` selects relative layer paths, and the frame assembles their complete bodies without editing lines. The Identity fixture additionally selects Identity. Shared layers contain no workplace identity or chosen filesystem root. Source files contain no comments.

Resource paths use `workplace-path`, the ordinary union of canonical absolute paths, canonical relative paths and `.`. Both captures and receiving signatures preserve the authored string. The frame joins relative resource slots before folding and applying them. A directory's first authored value supplies Start's directory context; the reader no longer joins it. A command's program path inside JSON is checked and resolved by the frame, while subsequent words and environment values remain literal. [The path-slot inventory](docs/path-slots.md) lists every position and the exact boundary.

Access records `statement A B C SCOPE PATH STATE`, `clearance A B C SCOPE NUMBER` and `label PATH NUMBER`. Scope is literal in the layer, and captured structural names lead the terms. No wide statement expands per seat. The frame consumes all recorded events, including equal duplicates and conflicting statements, rather than their coalesced auxiliary shadow cells. It resolves scoped replacements, clearance, labels, missing roots and contradictions.

A flat kinds registry declares each name once, and a seat selects a registered kind or none. Native ensures and counts reject unknown, absent, duplicate and mixed selections. Kind homes and shared places use ordinary view statements. The interface remains the six executable names server, session, window, pane, arrange and start. Provenance paths remain relative source addresses; they are never resource slots. The Structure body checks display-name uniqueness but does not independently reject different display names sharing a seat key; the frame retains its structural checks.

The auxiliary key-records cell is not that decision. No key is generated by the declarations, and cryptographic and socket mechanisms remain outside this source.

For any integration use a fresh isolated root and a new configuration clone. Never replace an existing workplace. The frame generates exactly `workdir : ROOT` and `server : NAME : CONF`, each with a newline, where ROOT is the actual root, NAME follows the clone-path rule, and CONF is the raw configuration path. Program addresses and source line counts are preserved. No command here starts a server.
